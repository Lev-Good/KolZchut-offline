# שרשרת אופליין של אתר "כל זכות"

## מטרת הפרויקט

ארכיון אופליין מלא של אתר "כל זכות" (kolzchut.org.il) לשימוש אישי/קהילתי, עם
מנגנון עדכון דלתא ומנגנון סינון תכנים בעייתיים.
התוצר הסופי הוא **ZIP אחד** שנפתח בדפדפן, עם טקסט, קישורים בין דפים, אינדקס
נושאים, חיפוש מקומי, ובדיקת גרסה מול GitHub Releases.

## טכנולוגיות

- Python 3.12+ — תלויות ב-[requirements.txt](../requirements.txt): `requests`, `beautifulsoup4`
- ארכיטקטורה: Python שמייצר HTML סטטי + JavaScript מקומי לחיפוש (ללא שרת)
- אחסון הארכיון בריפו: Git LFS (`kolzchut_out/**`)
- CI: GitHub Actions — שער בדיקות (`pr-check.yml`) + מיזוג ופרסום (`auto-merge.yml`)

## גישת רשת (מגבלות אמיתיות)

| נתיב | סטטוס | שימוש |
|---|---|---|
| MediaWiki Action API (`/w/he/api.php`) | חסום לרובוטים / `Disallow` ב-robots.txt | לא בשימוש האוטומציה |
| Sitemap NS0 | מותר | מקור האמת לרשימת הדפים + `lastmod` |
| דפי מאמרים (`/he/<page>`) | מותר, `Crawl-delay: 5` | הורדת דפים שהשתנו |
| GitHub-hosted runner | **403 מכל נתיבי האתר** (נבדק ב-run 38162887263) | לכן הסנכרון רץ מהמחשב של מעדכן מורשה |

## מה כן ומה לא

|---|---|
| כל ~7,371 דפי התוכן | תמונות (הוסר מההיקף לפי בקשת משתמש, 2026-10-11) |
| קישורים בין דפים | דפי שיחה, היסטוריית גרסאות, דפי ויקי פנימיים |
| אינדקס נושאים + חיפוש מקומי | פאנל ניהול (מבוצע דרך סקריפטים נפרדים) |
| מנגנון עדכון דלתא מבוזר | |

## מודל העדכון (דרישה מרכזית)

משתמשים מורשים מעדכנים את המאגר מהמחשבים שלהם בלבד: סנכרון מקומי → ענף נפרד →
Pull Request → בדיקות אוטומטיות ב-GitHub → מיזוג אוטומטי ופרסום Release, **ללא
אישור ידני וללא תלות במחשב או בשרת של המפתח**.

- הזדהות: חשבון GitHub אישי לכל מעדכן; אין אסימונים משותפים בקוד.
- אין דחיפה ישירה ל-master (Branch Protection עם required check `verify`).
- אין הרצת קוד לא מהימן עם הרשאות כתיבה: סקריפטי האימות נלקחים מ-master בלבד.
- אין פרסום חלקי: כשל בכל בדיקה משאיר את הגרסה המאומתת האחרונה באוויר.
- אוטו-מיזוג חל על שינויי תוכן בלבד (`kolzchut_out/**`, `docs/**`).

פירוט מלא, נוהלי הרשאה ותרחישי בדיקה: [DISTRIBUTED_UPDATES.md](DISTRIBUTED_UPDATES.md)
ו-[DECISIONS.md](DECISIONS.md).

## קריטריוני הצלחה

1. משתמש מורשה מפעיל `kolzchut_contribute.py` ומקבל PR שנפתח אוטומטית.
2. PR שעובר את כל הבדיקות ממוזג ל-master ומייצר Release חדש ללא התערבות.
3. PR שנכשל (כשל סנכרון, מחיקה חריגה, שינוי גודל חריג, מסנן לא מופעל) אינו ממוזג
   והגרסה הקודמת נשארת זמינה.
4. אין קוד לא מהימן שרץ עם הרשאות כתיבה למאגר.
